# Security Policy

## Reporting a vulnerability

Do not open a public issue for suspected vulnerabilities, leaked credentials, customer data, billing bypasses, SSRF, webhook forgery, or provider credential exposure.

Use GitHub private vulnerability reporting on the affected repository when available. Until a dedicated security address is published, contact an organization owner privately.

Include:

- affected repository and version;
- reproduction steps;
- expected impact;
- whether credentials or user data may be exposed;
- suggested mitigation, if known.

Do not include live credentials or third-party user data in the report.
